# ADR-0021: OWL 推論器(ELK)を CI に置く — 「矛盾は検出されなかった」と「矛盾がない」を区別する

- ステータス: 承認済み
- 日付: 2026-09-11

## コンテキスト

[ADR-0009](0009-ontology-operations.md) 決定1 は「形式的に決定可能なもの(構文、プロファイル適合、論理的整合性)は機械が確定的に判定する」と決めた。[ADR-0005](0005-reasoner-boundary.md) の補記(2026-09-01)はそのために OWL 推論器の導入を Phase 4 から Phase 2 へ前倒しした。

「決定可能なものを機械が判定する層」のうち、SHACL 検証(`P2A-05`)と想定質問(`P2B-07`)、廃止ライフサイクル([ADR-0017](0017-deprecation-lifecycle.md))は入っている。**残っていたのが OWL 推論**である。他と性質が違うのは、**Java の依存が入る**点だけのはずだった。

### 実装して測ったら、前提が間違っていた

ADR-0009 の根拠にはこう書いてある。

> 推論器(ELK / HermiT)は充足不能クラスと矛盾を exact に検出する。

**ELK についてはこれが成り立たない。** ELK 0.6.0 を実際に動かして測った結果が次である。

| 入力 | OWL 2 EL の逸脱 | ELK の結論 | 結論は完全か |
|---|---|---|---|
| EL の中で整合したオントロジー | 0 件 | 矛盾は検出されず | **完全** |
| **データプロパティ 1 個を持つだけのオントロジー** | **0 件** | 矛盾は検出されず | **不完全** |
| `rdfs:subClassOf` の左辺に `owl:unionOf` | **1 件** | 矛盾は検出されず | **完全** |
| 同梱サンプル `samples/retail-core.ttl` (公理 56 件) | 宣言漏れ 25 件 / 表現力 0 件 | 矛盾は検出されず | **不完全** |
| 互いに素な 2 クラスの共通部分となるクラス | 0 件 | **充足不能クラス 1 件** | 完全 |
| 個体が互いに素な 2 クラスに属する | 0 件 | **矛盾を検出** | 完全 |

読み取れることが 2 つある。

**1. ELK は実用的なオントロジーではほぼ常に不完全になる。** 原因はデータプロパティである。ELK 0.6.0 は `DataProperty` / `DataPropertyDomain` / `DataPropertyRange` / `FunctionalDataProperty` を扱えず、これらを含むオントロジーでは `Ontology satisfiability cannot be checked!` と警告して**整合性の判定そのものを諦める**。同梱サンプルはデータプロパティ 2 個・ドメイン 2 個・レンジ 2 個・関数的 1 個で、これに該当した。「業務用のオントロジーで属性を 1 つも持たない」ことは無いので、**不完全は例外ではなく通常の状態**である。

**2. プロファイル適合から不完全性は推測できない。両方向にずれる。** データプロパティは OWL 2 EL に**含まれる**ので逸脱 0 件なのに ELK は扱えない。逆に `rdfs:subClassOf` の左辺の `owl:unionOf` は逸脱として報告されるが、`(A ⊔ B) ⊑ C` は `A ⊑ C, B ⊑ C` と等価なので **ELK は完全に扱える**。つまり「OWL 2 EL プロファイルに適合していれば ELK の結論は完全」という近道は成立しない。

### 不完全さの向きは一方向である

ELK は扱えない公理を**無視する**。無視すると制約が減り、モデルの集合が広がり、導出される含意は減る。したがって:

- **検出したものは本物である**(偽陽性が無い。健全)
- **見逃しがある**(偽陰性がある。不完全)

CI のゲートとしては、この非対称性は好都合である。**通ったからといって正しいとは言えないが、落ちたら本当に悪い。**

### 依存とライセンスの調査

実装の前に配布物に何が入るかを確認した。

- **ELK** は Maven Central に `io.github.liveontologies:elk-owlapi:0.6.0` として公開されている。**Apache-2.0**
- **OWL API** (`net.sourceforge.owlapi`) は **Apache-2.0 と LGPL-3.0 のデュアルライセンス**。**Apache-2.0 の方を選択する**
- **ROBOT** (ontodev/robot) は BSD-3-Clause で、オントロジーの検査に広く使われている。**しかし配布 jar (82 MB) を実際に落として中身を列挙したところ `org/semanticweb/HermiT/...` と `jfact` が入っていた。** ADR-0005 決定4 が「HermiT (LGPL-3.0) は配布物に同梱しない」と決めているので使えない
- ビルドした shade jar (18.4 MiB) の中身を列挙し、`hermit` / `jfact` に一致するエントリが **0 件**であることを確認した

## 決定

### 1. 「矛盾は検出されなかった」と「矛盾がない」を区別し、結論の完全性を必ず併せて返す

これがこの ADR の中心である。JSON のフィールド名からこの区別を消さない。

| フィールド | 意味 |
|---|---|
| `inconsistency_found` | **矛盾が見つかったか**。`false` は「矛盾がない」ではない |
| `consistency_conclusive` | その結論が完全だったか。`false` なら見逃しがありうる |
| `incompleteness_reasons` | ELK が挙げた不完全さの理由(扱えなかった構文の一覧) |
| `unsatisfiable_classes` | 充足不能クラスの IRI。**測っていないときは `null`**(`[]` ではない) |
| `unsatisfiable_classes_conclusive` | 同上の完全性 |
| `reasoner` | 実際に走った推論器と版(`"ELK 0.6.0"`) |

実装上の帰結が 3 つある。

**(a) OWLAPI の `isConsistent()` / `getUnsatisfiableClasses()` を使わない。** あれは ELK の `IncompleteResult` を剥がして `boolean` / `Node` だけを返すので、**「完全に検査できた `false`」と「見逃しがあるかもしれない `false`」が区別できなくなる**。ELK 拡張の `checkIsConsistent()` / `computeUnsatisfiableClasses()` を使う。

**(b) 不完全さの理由は受け皿のロガーで回収する。** `IncompletenessMonitor` は「不完全か」を `boolean` で返すが、**理由は `logStatus(Logger)` にしか出さない**。そこで溜めるだけの SLF4J ロガー(`CapturingLogger`)を渡して回収する。ELK は `isInfoEnabled()` を見て詳細行を出すため、この受け皿は INFO を有効と答える。

**(c) 版を出力に刻む。** 不完全性の範囲は推論器の版で変わる。どの版が出した結論かが分からないと、後から読んだ人が範囲を誤解する。`getReasonerName()` は ELK 0.6.0 では `null` を返す(実測)ので、jar 内の `META-INF/maven/.../pom.properties` から版を読む。

**`null` と `[]` を区別するのは [ADR-0020](0020-health-metrics.md) 決定3 と同じ扱いである。** 矛盾したオントロジーでは全クラスが充足不能になるので列挙しない。そこで `[]` を返すと「充足不能クラスは無かった」と読めてしまう。

### 2. 止めるのは「確実に悪い」ものだけ。不完全さでは止めない

| 事象 | CI を止めるか | 理由 |
|---|---|---|
| 読み込めなかった | **止める** | 読めなかったことを「矛盾なし」にすると壊れたファイルがすり抜ける |
| 矛盾が検出された | **止める** | ELK は誤検出しないので本物である |
| 充足不能クラスが検出された | **止める** | 同上。そのクラスのインスタンスは存在し得ない |
| 結論が不完全だった | 止めない(報告する) | データプロパティ 1 個で該当するため、止めると実用的なオントロジーが全部落ちる |
| OWL 2 EL プロファイルの逸脱 | 止めない(報告する) | 逸脱は「矛盾している」ことを意味しない |

**不完全さで止めないのは「EL に収めろ」という設計上の強制をしないためである。** EL の外を書くのは OWL 2 DL として正当な選択であり、CI が禁じることではない。ADR-0005 は ELK を既定に選んだが、DL 全体を諦めたわけではない。

**その代わり、不完全だったことは必ず表示する。** `scripts/check-reasoning.sh` の要約は「矛盾は検出されませんでした (見逃しがありえます)」と書く。**ここで「矛盾なし」と書いたら、この ADR は目的を失う。**

### 3. プロファイル逸脱は「宣言漏れ」と「表現力」に分けて報告する

同梱サンプルの逸脱 25 件は**すべて `UseOfUndeclared*`**、つまり SKOS と SHACL の語彙を `owl:AnnotationProperty` として宣言せずに使っていることによる指摘だった。これは推論の結論に影響しない(OWLAPI は未宣言でも公理として扱う)。

**分けないと、意味のある逸脱が宣言漏れの山に埋もれる。** `declaration_violations` と `expressivity_violations` を別に数え、別に出す。

### 4. 依存は ELK と、ELK が引く OWL API だけにする

`containers/reasoner/pom.xml` は `elk-owlapi` と `slf4j-simple` だけを直接の依存に持つ。**OWL API は明示的に足さない。**

理由は実測した事故である。当初 `owlapi-distribution:5.5.1`(uber-jar)を足していた。ELK は `owlapi-apibinding:5.1.20` 経由で api / impl / **parsers** / rio / tools / oboformat をすべて引くため、**同じクラスが 2 つ classpath に載った**。`owlapi-rio:5.1.20` が期待する rdf4j と `owlapi-distribution:5.5.1` が引く rdf4j 5.0.2 が食い違い、Turtle の読み込みが次で落ちた。

```
java.lang.NoSuchFieldError: Class org.eclipse.rdf4j.rio.helpers.BasicParserSettings
does not have member field 'org.eclipse.rdf4j.rio.RioSetting VERIFY_DATATYPE_VALUES'
  at org.semanticweb.owlapi.rio.RioParserImpl.parseDocumentSource(RioParserImpl.java:174)
```

**OWL API は ELK が対応している版(5.1.20)に揃える。** 推論の結論の正しさは、ELK が実際にテストされている API に依存する。新しい API に上げて壊れても静かに壊れる。

この事故はもう 1 つのことを教えた。**`NoSuchFieldError` は `Exception` ではなく `LinkageError` なので `catch (Exception)` を素通りし、プロセスが落ちて JSON が出なかった。** 依存の不整合は実際に起きる故障モードなので、ファイル単位の検査は `Exception | LinkageError` を捕まえて「検査できなかった(= 止める)」として報告する。`OutOfMemoryError` と `StackOverflowError` は**あえて捕まえない** — JVM の状態が壊れた後に出した結論は信用できないので、プロセスごと落ちる方が安全である(終了コードが 0 にならないので CI は止まる)。

### 5. CI で検査するが、`approve` の同期パスには入れない

[ADR-0005](0005-reasoner-boundary.md) 決定3(推論を Core API の同期パスに入れない)を維持する。CI が検査するのは**このリポジトリが同梱するオントロジー**(`samples/` とテストデータ)である。利用者のオントロジーに対する承認時の検査は SHACL(`P2A-05`)と廃止ライフサイクル(ADR-0017)が担当する。

`.github/workflows/ci.yml` の `reasoner` ジョブは 2 段構えである。

1. `containers/reasoner/reasoner-check.test.sh` — **検査自身の振る舞い**を固定する。「矛盾を検出したら止める」「読めなかったら止める」「結論が不完全でも止めない」の 3 方向を見る。**片方向だけだと、常に通す実装と常に止める実装のどちらも通ってしまう**
2. `scripts/check-reasoning.sh samples` — 同梱サンプルを全部検査する。サンプルが増えたときにここで捕まえる

### 6. 出力は標準出力の JSON、ログは標準エラー

呼び出し側が結果を機械的に読めるようにする。ELK は推論の各段階を INFO で出すので、`simplelogger.properties` で標準エラー側を WARN 以上に絞る(**不完全性の警告は WARN なので残る**)。

OWLAPI の `UnparsableOntologyException` は「試した全パーサのログ」を連結した数万文字を返すため、JSON に載せるメッセージは 2,000 文字で切り、**全文は標準エラーに出す**。

## 検討した代替案

### ROBOT を使う

**却下。** ROBOT (ontodev/robot) はオントロジー検査のデファクトのコマンドライン道具で、`robot reason` / `robot validate-profile` がまさにこの用途である。自分で Java を書く必要がなくなる。

却下理由: **配布 jar が HermiT と JFact を同梱している。** 82 MB の `robot.jar` を落としてエントリを列挙し、`org/semanticweb/HermiT/...` が入っていることを確認した。ADR-0005 決定4(HermiT を配布物に同梱しない)に反する。ROBOT 自身のライセンス(BSD-3-Clause)の問題ではなく、**同梱物の問題**である。

依存を自分で選べる形(直接 `elk-owlapi` に依存する)なら、イメージに入るものを完全に制御できる。**「便利な道具」より「中身が説明できること」を採る。**

### OWL API を 5.5.1 に上げ、ELK 側の OWL API を除外する

**却下。** 新しい API とパーサを使える。

却下理由: ELK 0.6.0 は 5.1.20 に対して公開されている。**推論の結論の正しさが、テストされていない組み合わせに依存する**ことになる。しかも壊れ方が静かである可能性がある(今回はたまたま `NoSuchFieldError` で派手に落ちたが、`AbstractMethodError` のように条件次第でしか出ない壊れ方もある)。**推論器が既定で入れている版に揃える。**

### プロファイル逸脱の件数から不完全性を推測する

**却下。** `OWL2ELProfile` の報告だけで済むなら、ELK の内部 API(`IncompleteResult` / `IncompletenessMonitor`)に触らずに書ける。

却下理由: **実測で両方向にずれた**(上記「実測して分かったこと」の表)。データプロパティは EL に含まれるので逸脱 0 件なのに ELK は扱えず、`subClassOf` の左辺の `owl:unionOf` は逸脱 1 件なのに ELK は完全に扱える。**この近道を採ると、実用的なオントロジーに対して「逸脱 0 件、矛盾なし」という完全に誤解を招く報告を返す。**

この 2 つのケースは `containers/reasoner/testdata/incomplete-datatype.ttl` と `beyond-el.ttl` として残し、両方向を回帰テストで固定した。

### 結論が不完全ならビルドを止める(EL に収めることを強制する)

**却下。** 「CI が通ったら整合性は完全に検査済み」という強い保証が得られる。

却下理由: **同梱サンプルを含め、実用的なオントロジーがほぼ全部落ちる。** データプロパティを 1 つ書くだけで該当する。EL に収めるかどうかは**そのオントロジーの持ち主が決めること**で、CI の既定にはしない。

必要になったら「このリポジトリのサンプルは EL に収める」という別の規約として、`--require-conclusive` 相当のオプションを足せばよい。**今は要求が無いので作らない。**

### HermiT を既定にして完全な OWL 2 DL 推論を行う

**却下。** ADR-0005 決定4 を維持する。LGPL-3.0 のコンポーネントを配布物に入れない方針は変えていない。

なお **HermiT を入れれば不完全性の問題は消える**ので、これは技術的には有効な解である。ライセンスの判断で採らない。ADR-0005 が残した「任意有効化」の経路も、この ADR では実装しない(要求が無い)。

### `approve` に組み込んで承認時に検査する

**却下。** ADR-0005 決定3。推論の実行時間は予測しづらく、同期パスに入れるとタイムアウトの設計が破綻する。

なお ELK は OWL 2 EL の範囲では多項式時間で動く。しかし**「範囲内なら速い」は「範囲外の入力が来ない」を意味しない。** 入力はユーザーが書くものである。

### 推論で導出された含意をトリプルストアに射影する

**却下(スコープ外)。** 「エージェントに導出済みの含意を渡せる」ことは価値がある(ADR-0005 が「単なる語彙集との差別化」と書いた部分)。

却下理由: [ADR-0002](0002-triple-store-as-rebuildable-projection.md) の「トリプルストアは正本の射影」という不変条件と、「推論で増えたトリプルは正本に無い」という事実の関係を先に決める必要がある。**この ADR の範囲は「CI で検査する」までとし、含意の射影は別の決定として扱う。** バックログに `P2B-15` として記録する。

## 結果(トレードオフ・影響)

### 受け入れるコスト

- **Java のビルドが CI に入った。** ADR-0005 が「先送りしただけであり、消えたわけではない」と書いたコストの支払いである。**キャッシュなしのイメージビルドが 51 秒**(実測。maven の依存解決を含む)。実行イメージは 513 MB(JRE + shade jar 18.4 MiB)
- **検査の結論がほぼ常に「不完全」になる。** 運用者がこれを読み流すようになるリスクは現実的である。要約の文言(「見逃しがありえます」)以外の対策は打っていない。**指標を出すことと、指標が読まれることは別問題である**
- **ELK 0.6.0 に固定される。** 版を上げると不完全性の範囲が変わり、`testdata/incomplete-datatype.ttl` の期待が変わりうる。テストが落ちることでそれに気づく設計になっている
- **OWL API 5.1.20 に固定される。** ELK が新しい OWL API に対応するまで上げられない
- **検査の対象がこのリポジトリの同梱物だけである。** 利用者のオントロジーは承認時の SHACL と廃止検査でしか見ない

### 得られるもの

- **偽陽性のないゲート。** 落ちたら本当に悪い。CI の警告を無視する習慣を作らない
- **「測れなかった」を「問題なし」と言わない。** [ADR-0016](0016-semantic-diff.md) 決定5(空白ノードが多すぎて差分を計算できなかった)、[ADR-0020](0020-health-metrics.md) 決定3(測れなかった指標は `null`)に続く 3 例目である。**同じ原則が 3 か所で必要になったので、これは偶然ではなく設計の芯である**
- **配布物の中身を説明できる。** 依存を自分で選んでいるので、jar に何が入っているかを列挙して示せる
- **ADR-0009 の前提の誤りが記録に残った。** 「推論器は exact に検出する」という一般論が、具体の推論器では成り立たなかった

### 影響を受ける他の決定

- [ADR-0005](0005-reasoner-boundary.md) — 補記を追加した(推論器の同期パス排除と HermiT 非同梱は維持、ELK の不完全性を追記)
- [ADR-0009](0009-ontology-operations.md) — 補記を追加した(決定1 の「健全かつ完全な決定手続きが存在する」は ELK には当てはまらない)
- [ADR-0016](0016-semantic-diff.md) / [ADR-0020](0020-health-metrics.md) — 同じ原則(計算・測定できなかったことを問題なしと混同しない)の 3 例目
- [`../third-party-licenses.md`](../third-party-licenses.md) — ELK / OWL API / SLF4J / ROBOT の調査結果を反映した
