# ADR-0033: 孤児のマニフェストは消す — 正本ではないものに保守的である理由が無い

- ステータス: 承認済み
- 日付: 2026-09-12

## コンテキスト

`reconcile` の `orphan_blobs` は **`.ttl` だけ**を列挙する
(`OntologyBlobStore.list_versions` が `.endswith(".ttl")` で絞っている)。

したがって `versions/<ns>/_state.json` は視界に入らない。名前空間を削除した
後(公開済み TTL が 1 件も無い場合は削除できる)、**マニフェストだけが残る**。
`P2B-20` である。

害は小さい — 誰も読まないファイルが 1 つ残るだけである。**しかし
「検出できていない」ことは検出できていないままである。**

## 決定

### 1. 孤児のマニフェストを検出して**消す**

`reconcile` が `orphan_manifests` として報告し、**同じ実行で削除する**。

`orphan_blobs`(`.ttl`)と扱いを分ける。**判断できる根拠が違う。**

| もの | 扱い | 理由 |
|---|---|---|
| `.ttl`(`orphan_blobs`) | **報告するだけ** | **正本である**(不変条件7 — 公開済みの版は削除しない) |
| データセット(`orphan_datasets`) | **報告するだけ** | 削除が破壊的で、DB 側の行が別の理由で失われていた場合にデータを消す |
| 名前付きグラフ(`graphs_removed`) | **削除する** | このシステムが組み立てた IRI で、失っても正本から再構築できる |
| **マニフェスト** | **削除する** | **PostgreSQL の状態の射影であり正本ではない**([ADR-0010](0010-approval-and-projection.md) 決定7) |

マニフェストは `graphs_removed` と同じ側である。**正本ではないものに対して
保守的である理由が無い** — 失っても `_refresh_manifest` / `reconcile` が
作り直す。

### 2. 削除の口はマニフェストしか指せない形にする

`OntologyBlobStore` には**これまで削除のメソッドが 1 つも無かった**。
追加するのは `delete_manifest(namespace)` だけである。

```python
async def delete_manifest(self, namespace: str) -> bool: ...
```

**引数が名前空間名であり、パスではない。** パスは `manifest_path_for` が
組み立てるので、**このメソッドで `.ttl` を消すことは構造的にできない**。

一般的な `delete_blob(path)` にしない。**署名の狭さが強制である** —
「TTL を消さない」を規約やレビューで守るより、呼べない形にするほうが強い
(不変条件5 で名前空間名の検証を `validate_namespace_name` に集約したのと
同じ考え方)。

### 3. 消したことを報告から消さない

`orphan_manifests` は**削除に成功しても残す**。
[ADR-0013](0013-reconcile-repairs-observed-divergence.md) 決定5
(`missing_graphs` と `graphs_repaired` を両方残す)と同じ判断である。

**修復した事実を隠すと上流の原因が見えなくなる。** 孤児のマニフェストが
毎回出るなら、名前空間の削除経路に取りこぼしがある。

### 4. 「正本に無い名前空間」の判定は PostgreSQL に置く

孤児の定義は「`versions/<ns>/_state.json` があるのに `<ns>` が
`namespaces` に無い」である。**Blob 側の他の痕跡(`.ttl` の有無)は見ない。**

`.ttl` が残っている場合もマニフェストは消す。**そのほうが安全側である** —
マニフェストが無いとローダはその名前空間を丸ごとスキップするので
(`build_tdb` の「マニフェストが取得できません」経路)、**削除したはずの
名前空間が Blob から復活しない**。

ただしこれは**副作用として安全側に転ぶだけ**で、復活を防ぐ機構ではない。
復活を防いでいるのは `DELETE` の 409(公開済み TTL があれば削除しない)で
あり、そこは変えていない。

## 検討した代替案

### 報告するだけにする(`orphan_blobs` と揃える)

**却下(決定1)。** 一貫して見えるが、**揃える理由が無い**。
`orphan_blobs` が報告だけなのは**正本だから**で、マニフェストは正本では
ない。性質の違うものを扱いが同じという理由だけで揃えると、
「なぜ消さないのか」の答えが「他と同じだから」になる。

### `list_versions` の `.ttl` の絞り込みを外して一般化する

**却下。** 1 行で済む。

却下理由: **`orphan_blobs` の意味が変わる。** あれは「正本に対応する行が
無い TTL」であり、そこにマニフェストが混ざると**報告を読んだ運用者が
「消してはいけない TTL」と「消してよいマニフェスト」を手で選別する**ことに
なる。列を分けるほうが読める。

### 一般的な `delete_blob(path)` を追加する

**却下(決定2)。** 将来の用途に使える。

却下理由: **TTL を消せる口を開ける。** 不変条件7 は「公開済みの版を削除
しない」と言っており、それを**呼べない形で担保できる**なら、そうする。

## 結果(トレードオフ・影響)

### 受け入れるコスト

- **Blob ストアに削除のメソッドが 1 つ増える。** 狭い署名で限定した(決定2)
- **`reconcile` が Blob の一覧をもう 1 回引く**(マニフェスト用)。
  `.ttl` の一覧とは絞り込みが違うため
- **`.ttl` が残っている孤児でもマニフェストを消す**(決定4)。ローダの
  スキップ経路に落ちる

### 得られるもの

- **`P2B-12` の残りが閉じた。** `reconcile` の視界に入っていなかったものが
  入った
- **正本とそうでないものの扱いが、理由付きで分かれた**(決定1)
- **TTL を消せる口を開けずに済んだ**(決定2)

### 影響を受ける他の決定

- [ADR-0013](0013-reconcile-repairs-observed-divergence.md) — 報告の欄が
  1 つ増えた。決定5(修復しても報告から消さない)を再利用した
- [ADR-0010](0010-approval-and-projection.md) 決定7 — マニフェストが正本では
  ないという性質が、削除してよい根拠になった
