# ADR-0039: 束縛が無い結果に行数 `0` を作らない — `ASK` を特別扱いしない

- ステータス: 承認済み
- 日付: 2026-09-12

## コンテキスト

[ADR-0034](0034-construct-describe.md) 決定7 は `CONSTRUCT` / `DESCRIBE` の
`returned_row_count` を `NULL` にした。

> **`0` を書かない** — 「0 行返した」と「行という概念が無い」は違う

そのとき `ASK` は**既存の振る舞いを変えなかった**(`P2B-22` として記録)。
`ASK` の結果は SPARQL Results JSON で

```json
{ "head": {}, "boolean": true }
```

であり `results.bindings` を持たない。`_row_count` は束縛が見つからないと `0` を
返すので、**`true` と答えた `ASK` が「0 行返した」として記録されていた。**

### これは `ASK` の問題ではない

`_row_count` は**形が読めなかったときにも `0` を返す**。

```python
def _row_count(results: Any) -> int:
    if not isinstance(results, dict):
        return 0  # 読めなかった → 0
    section = results.get("results")
    if not isinstance(section, dict):
        return 0  # ASK もここ → 0
    bindings = section.get("bindings")
    return len(bindings) if isinstance(bindings, list) else 0
```

**`0` を作っているのが本体である。** `ASK` はそれが日常的に起きる経路にすぎない。
[ADR-0001](0001-rdf-store-selection.md) が「SPARQL 1.1 Protocol をハード境界に
する」と決めている(= ストアを差し替えられる)ので、**持ち込みストアが想定外の
形を返したときにも同じ誤りが起きる。**

`ASK` だけを分岐で特別扱いすると、この本体が残る。

## 決定

### 1. `_row_count` は `int | None` を返す。`0` を作らない

束縛の配列が見つからなければ `None` を返す。

| 結果の形 | `returned_row_count` |
|---|---|
| `results.bindings` が配列 | **その長さ**(空配列なら `0`。これは測った `0` である) |
| `boolean` がある(`ASK`) | **`NULL`** |
| 読めない形 | **`NULL`** |

**空の配列の `0` は残す。** 「`SELECT` が 0 行返した」は測った事実であり、
「行という概念が無い」とは違う。区別しているのはまさにここである。

### 2. `ASK` 専用の分岐を作らない

上の表に `ASK` という語は要らない — 「束縛が無い」で足りる。

**形で分岐すると本体が残る。** `results.get("boolean") is not None` を見る
実装にしても、持ち込みストアが `ASK` に別の形を返したときに再び `0` が生まれる。
**「束縛を数えられたか」だけを見れば、形の数え上げが要らない。**

### 3. 列を足さない。`ASK` の真偽値もクエリの形も記録済みの情報から辿れる

| 知りたいこと | どこから辿るか |
|---|---|
| `ASK` の答え(真偽値) | **記録したクエリと版で再実行する** |
| クエリの形(`ASK` か `SELECT` か) | **`query_text` の先頭**に残る |

真偽値を保存しない理由は [ADR-0018](0018-context-access-log.md) 決定1 が
用語の一覧を保存しなかった理由と同じである。

> オントロジーは不変リビジョンなので(不変条件7)、**記録したクエリと版で
> 再実行できる**。件数だけを持つ。

形を保存しない理由は、**`query_text` に既にあるから**である。切り詰めは
先頭 2,000 文字を残すので、形のキーワード(先頭付近にある)は消えない。
`ontology_core.sparql.guards.query_form` がそれを読む関数として既にある。

**記録済みのものに名前を付けるだけの列を足さない。** 列が増えるほど
「どちらが正しいのか」という問いが生まれる。

### 4. 既存の行は書き換えない

この変更より前に記録された `ASK` の行は `0` のままである。

**移行できない。** 行から形を判別するには `query_text` を解析することになり、
**正本を推測で書き換える**ことになる。そして `0` と記録された行には
**本当に 0 行だった `SELECT`** が混ざっている — 判別を誤れば測った事実を
消す。

[ADR-0027](0027-revision-lineage.md) 決定4 と
[ADR-0035](0035-actor-type.md) 決定3 と同じ判断である。**「問うていない」を
書き換えない。**

### 5. `SELECT` で行数が測れなかったら警告としてログに残す

決定1 は**新しい `NULL` の理由**(読めなかった)を作る。それを黙って `NULL` に
するのは、このリポジトリが繰り返し避けている形である。

`_record_access` はクエリの形を判定できる(`query_form`)ので、
**`SELECT` なのに行数が `NULL` になったときだけ**警告を出す。`ASK` の `NULL` は
正常なので出さない。

**アクセスログの記録自体は続ける。** 読み取りの副産物であって前提条件では
ない(ADR-0034 決定3 と同じ向き)。

## 検討した代替案

### `ASK` の分岐を足して `NULL` にする

**却下(決定2)。** 変更が 1 行で済む。

却下理由: **`0` を作っている本体が残る。** 読めない形のときに `0` を返す
振る舞いはそのままで、持ち込みストアで同じ誤りが起きる。

### `returned_boolean` 列を足す

**却下(決定3)。** `ASK` の行が結果について何も語らない状態が解ける。

却下理由: **再実行できる**(ADR-0018 決定1 と同じ理由)。オントロジーは
不変リビジョンなので、記録したクエリと版があれば同じ答えが出る。
`used_graph_clause` が真のときは版だけでは足りないが、それは既に旗で
見せている問題である。

### `query_form` 列を足す

**却下(決定3)。** `ASK` の `NULL` と「読めなかった」の `NULL` が列だけで
区別できる。

却下理由: **`query_text` に既にある。** 記録済みのものに名前を付けるだけの
列は、食い違ったときにどちらが正しいのか分からなくなる。

### 既存の `0` を `NULL` に移行する

**却下(決定4)。** 読み手が過去の行も同じ規則で読める。

却下理由: **本当に 0 行だった `SELECT` を巻き込む。** 判別するには
`query_text` の解析が要り、**正本を推測で書き換える**ことになる。

### 読めない形のときに例外にする

**却下。** 異常が見逃されない。

却下理由: **記録のために本来の応答を壊さない**(ADR-0018 が繰り返している
判断)。アクセスログは読み取りの副産物である。決定5 の警告で十分に見える。

## 結果(トレードオフ・影響)

### 受け入れるコスト

- **`ASK` の行は結果について何も語らない**(決定3)。`returned_row_count` と
  `returned_triple_count` がどちらも `NULL`、`terms` は空である。答えを知るには
  クエリと版で再実行する
- **`NULL` に 2 つの理由が同居する**(決定1)。「行という概念が無い」と
  「読めなかった」である。**`query_text` の形で区別できる**ので列は足さないが、
  **列だけを見ると区別できない**。`SELECT` の側は決定5 の警告で見える
- **この変更より前の `ASK` の行は `0` のままである**(決定4)。集計するときは
  期間で切る必要がある
- **`returned_row_count` を読むコードは `None` を扱わなければならない**。
  ADR-0034 決定7 で既に `NULL` 可になっているので、型の上では変わらない

### 得られるもの

- **`true` と答えた `ASK` が「何も返さなかったクエリ」として数えられなくなる**
- **`0` を作る経路が消えた**(決定1・2)。`ASK` だけでなく、持ち込みストアが
  想定外の形を返したときにも `0` を作らない
- **`SELECT` の応答が読めなかったことが見える**(決定5)。以前は `0` に
  紛れていた

### 影響を受ける他の決定

- [ADR-0034](0034-construct-describe.md) 決定7 — 補記を追加した(`ASK` も
  `NULL` になった。**行の概念が無いものすべてが `NULL` になり、規則が 1 つに
  なった**)
- [ADR-0018](0018-context-access-log.md) 決定1 — 「再実行できるから保存しない」
  を `ASK` の真偽値にも適用した(決定3)
- マイグレーションは要らない。`returned_row_count` は 0009 で既に `NULL` 可に
  なっている
