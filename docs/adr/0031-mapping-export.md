# ADR-0031: 領域間マッピングを射影せず、標準の RDF として書き出す

- ステータス: 承認済み
- 日付: 2026-09-12

## コンテキスト

[ADR-0023](0023-cross-domain-mappings.md) 決定7 は「トリプルストアには射影
しない。API と MCP で提供する」と決め、**「射影するかは要求が出てから決める」**
として `P2B-17` に分離した。同 ADR が受け入れたコストにはこうある。

> **マッピングが SPARQL で引けない**(決定7)。エージェントは MCP ツール経由で
> しか見えない。**SPARQL だけを使う既存のクライアントからは見えない**

これが `P2B-17` である。**「射影しない」を確定させるだけでは、この問題は
そのまま残る。**

### `P2B-15` と同じ問題ではない

[ADR-0028](0028-no-entailment-projection.md)(`P2B-15`)は推論で導出された
含意を射影しないと決めた。理由の 1 つは「**ELK の結論が不完全なので、載るのは
中途半端な部分閉包になる**」だった。

**マッピングは違う。** マッピングは正本(PostgreSQL)にあり、完全で、
`owner` が `reason` 付きで宣言した確定した事実である。**「不完全なものを
載せる」問題は無い。** だから同じ結論になるとは限らない。

## 決定

### 1. トリプルストアには射影しない

理由を 4 つ挙げる。**(c) と (d) は `P2B-18` を実装した後に見えたもの**である。

#### (a) ローダは PostgreSQL を読まない

`containers/fuseki/load-snapshot.sh` は **Blob の `.ttl` だけ**を見て名前空間ごとの
TDB2 を組み立てる(**PostgreSQL を一切参照しない**)。射影したマッピングの
グラフは**レプリカの再作成で消える**。

`reconcile`([ADR-0013](0013-reconcile-repairs-observed-divergence.md))を
拡張して回収する道はある(マッピングは正本にあるので、含意と違って**再計算
ではなく再射影**で足りる)。しかし**ローダ自身に DB 依存を入れる**のは
[ADR-0002](0002-triple-store-as-rebuildable-projection.md) の
「ストアは Blob だけから作り直せる」という前提を変える。起動経路に
PostgreSQL への到達性が加わると、**射影の再構築が正本の別の半分の可用性に
依存する**。

#### (b) どの版にも属さないので置き場所が無い(決定7 の元の理由)

- マッピングは**どの版にも属さない**ので版の名前付きグラフに混ぜられない
- 既定グラフは常に単一の承認済み版である([ADR-0010](0010-approval-and-projection.md) 決定6)
- 専用グラフ(`urn:ontology:mapping/...`)は**エージェントに `GRAPH` 句の
  知識を要求する**

#### (c) `P2B-18` で作った区別が、射影の経路では全部消える

[ADR-0030](0030-mapping-target-lifecycle.md) は終点の生死を 4 状態
(`deprecated` / `active` / `absent` / `unknown`)で返すと決めた。
**射影したグラフを SPARQL で引いた側には、そのどれも分からない。**

`<sales:Gold> skos:closeMatch <finance:Retired>` というトリプルだけが載る。
引いた側は**その先が廃止されていることも、権限が無くて調べていないことも
区別できない**。ADR-0030 が 4 状態に分けた労力が、この経路では無駄になる。

**「少しだけ正しい」情報を静かに置くことになる。** ADR-0028 決定2 が
「少しだけ推論する」を拒否したのと同じ形である。

#### (d) 権限の粒度が合わない

ADR-0030 決定1 は「**相手の名前空間を読む権限が無ければ生死を返さない**」と
決めた。射影したグラフは**名前空間のデータセット単位でしか権限を持てない**
(ADR-0001 の物理分離)。`N` のデータセットに載せた瞬間、`N` の分析者は
相手の権限に関わらずそれを引ける。

### 2. 代わりに標準の RDF として書き出す

`GET /namespaces/{ns}/mappings/export` が `text/turtle` を返す。
絞り込み(`direction`)は JSON の一覧と同じで、権限も同じ `data-analyst`
である。

**[ADR-0026](0026-provenance-export.md) と同じ形にする。** あちらも
「トリプルストアには射影しないが、W3C 標準の RDF としては出せるようにする」
という判断だった。**表現ごとに別の URL を持つ流儀を 1 つに保つ** —
内容交渉(`Accept: text/turtle`)にしないのは ADR-0026 の代替案と同じ理由で、
JSON と RDF で同じ URL が違う振る舞いをする形を作らないためである。

これで「SPARQL だけを使うクライアントからは見えない」は
**「自分のストアへ読み込める」**に変わる。射影のライフサイクル((a))を
こちらが抱えずに済む。

### 3. SKOS のトリプルと、記述ノードの両方を出す

```turtle
<https://e.example/sales#Gold> skos:closeMatch <https://e.example/finance#Retired> .

<urn:ontology:mapping/sales-ns/...> a ont:Mapping ;
    ont:source <https://e.example/sales#Gold> ;
    ont:target <https://e.example/finance#Retired> ;
    ont:predicate skos:closeMatch ;
    ont:declaredIn "sales-ns" ;
    ont:declaredBy <urn:ontology:agent/s-owner-oid> ;
    ont:declaredAt "2026-09-12T…"^^xsd:dateTime ;
    rdfs:comment "同じ顧客区分を指している" ;
    ont:targetStatus "deprecated" ;
    ont:targetSuccessor <https://e.example/finance#KeyAccount> ;
    ont:reciprocal false ;
    ont:disputed false .
```

**素の SKOS トリプルを出すのは安全である。** ADR-0023 決定1 が述語を SKOS の
5 つに限ったのは、まさに**論理的帰結を持たない**からである。載せても推論器が
制約を流し込まない。

**そして記述ノードにメタデータを載せる。** `reason` / `declared_by` /
`target_status` は SKOS のトリプルには載らない情報で、これが無いと
(c) と同じ状態になる。

**記述ノードに IRI を与える。空白ノードにしない。** 空白ノードだと
再取得したときに同じノードだと分からず、2 回の書き出しを差分比較できない
(このリポジトリは空白ノードの扱いで既に痛い目を見ている。ADR-0016 決定5)。

### 4. `ont:targetStatus` は必ず出す。`unknown` も含めて

`unknown` のときも `ont:targetStatus "unknown"` と `ont:targetStatusNote` を
出す。**省略すると「問題なし」と読まれる。**

[ADR-0016](0016-semantic-diff.md) 決定5 / [ADR-0020](0020-health-metrics.md)
決定3 / [ADR-0021](0021-owl-reasoning-in-ci.md) 決定1 /
[ADR-0022](0022-competency-question-sets.md) 決定5 /
[ADR-0025](0025-result-limit-enforcement.md) 決定3 / ADR-0026 決定5 /
ADR-0027 決定5 / ADR-0030 決定1 と**同じ原則の 9 例目**。

### 5. 書き出しは「読んだ人の行為」であって、静かな事実ではない

決定1 の (c) は書き出しにも当てはまる — **素の SKOS トリプルだけを読む
消費者は、終点の生死を見落とす。**

それでも射影と違うのは、**書き出しは運用者が明示的に取得して自分のストアへ
読み込む行為**だという点である。射影は**エージェントが知らないまま引く
静かな事実**になる。同じ情報の欠落でも、**誰がそれを引き受けるかが違う。**

この区別を曖昧にしないために、README とツールの説明に
「**素の SKOS トリプルだけを読むと終点の生死は分からない**」と書く。

### 6. 開け直す条件を 3 つとも満たしたときに限る

`P2B-17` を閉じるが、条件を明記する。**3 つすべてが必要**である
(ADR-0028 決定5 と同じ書き方)。

1. **ローダがマッピングを再射影できる。** Blob だけから作り直せるという
   ADR-0002 の前提を壊さない形で((a))
2. **終点の生死が射影したグラフでも伝わる**((c))。独自述語を射影に混ぜるか、
   別の手段を決める
3. **権限の粒度が合う**((d))。相手の名前空間を読めない主体に生死が漏れない

## 検討した代替案

### 専用の名前付きグラフへ射影する

**却下(決定1)。** 決定7 が既に挙げた理由((b))に加えて (a)(c)(d) が残る。

### 各名前空間のデータセットの既定グラフへ混ぜる

**却下。** `GRAPH` 句が要らなくなるのでエージェントから最も引きやすい。

却下理由: **ADR-0010 決定6(既定グラフは常に単一の承認済み版)を壊す。**
`P1-C1` の Critical はまさに既定グラフに版以外のものが混ざったことだった。
そして混ぜると**マッピングと版のトリプルが区別できなくなる** — ADR-0026
決定2 が拒否した「主張と導出が混ざる」と同じ形である。

### 内容交渉(`Accept: text/turtle`)にする

**却下(決定2)。** URL が増えない。

却下理由: **ADR-0026 が同じ判断で別の URL を選んでいる。** 流儀を 2 つ持つと、
「この API は内容交渉するのか、パスが分かれるのか」が表現ごとに違うことに
なる(`P2A-11` でパスパラメータ名を揃えたのと同じ、契約の一貫性の話である)。

### 素の SKOS トリプルだけを書き出す(記述ノードを作らない)

**却下(決定3)。** 出力が小さく、標準だけで済む。

却下理由: **`reason` が落ちる。** ADR-0023 決定5 は `reason` を必須にした —
「なぜ同じ(近い)と言えるのか」が無いマッピングは根拠にならない。
`target_status` も落ちる((c))。**標準に写すために情報を落とすのは本末転倒
である**(ADR-0026 決定4 と同じ判断)。

### 何もしない(決定7 を確定させるだけ)

**却下。** `P2B-17` は「決める」項目なので、「射影しない」と書けば形式的には
閉じる。

却下理由: **ADR-0023 が挙げた問題(SPARQL だけを使うクライアントから見えない)
が 1 ミリも動かない。** 決定だけを書いて問題を残すのは、このリポジトリが
嫌う「宣言はあるが強制されていない」の裏返しである。

## 結果(トレードオフ・影響)

### 受け入れるコスト

- **SPARQL で直接は引けないままである。** 書き出しを取得して自分のストアへ
  読み込む手順が要る
- **書き出しは時点のスナップショットである。** 取得した後に宣言や廃止が
  起きても追随しない(射影しないことの当然の帰結)
- **素の SKOS トリプルだけを読む消費者は終点の生死を見落とす**(決定5)。
  README とツールの説明で伝えるしかない
- **記述ノードの IRI は `urn:` で dereferenceable ではない**(ADR-0026 と同じ)

### 得られるもの

- **標準の RDF として取り出せる。** 「W3C 標準に忠実」の看板が、この成果物にも
  適用された(ADR-0026 と同じ回収)
- **射影のライフサイクルを抱えない**((a))。ローダに DB 依存が入らない
- **`P2B-18` の 4 状態が書き出しでは伝わる**(決定3・4)。射影では伝わらない
- **権限の粒度が保たれる**((d))。書き出しも `resolve_target_lifecycles` を
  通るので、相手を読めない主体には `unknown` が出る

### 影響を受ける他の決定

- [ADR-0023](0023-cross-domain-mappings.md) 決定7 — 「要求が出てから決める」に
  決着を付けた。**射影しない**が、書き出しを用意した
- [ADR-0026](0026-provenance-export.md) — 「射影せず W3C 標準で書き出す」という
  形を再利用した。**別の URL にする流儀も揃えた**
- [ADR-0030](0030-mapping-target-lifecycle.md) — 4 状態が書き出しにも載る。
  射影しない理由の 2 つ((c)(d))はこの ADR から来ている
- [ADR-0028](0028-no-entailment-projection.md) — 「少しだけ正しい情報を静かに
  置かない」という論法を再利用した
