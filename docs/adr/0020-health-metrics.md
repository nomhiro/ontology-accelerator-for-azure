# ADR-0020: 健全性指標は正本から測り、測れなかったことを隠さない

- 状態: 採用
- 日付: 2026-09-10
- 関連: [ADR-0009](0009-ontology-operations.md) 決定5（健全性を測る）、[ADR-0002](0002-triple-store-as-rebuildable-projection.md)（ストアは再構築可能な射影）、[ADR-0018](0018-context-access-log.md)（アクセスログ）、[ADR-0015](0015-term-owners.md)（用語単位の責任者）、[ADR-0016](0016-semantic-diff.md)（「計算できなかった」を「差分が無い」と混同しない）、[ADR-0005](0005-reasoner-boundary.md) / `P2A-05`（SHACL 検証）、バックログ `P2B-06`

## コンテキスト

[ADR-0009](0009-ontology-operations.md) 決定5 は「**測っていないものは、致命的になるまで見えない**」として 6 項目を挙げた。

| # | 項目 | 原資料 | 揃った時期 |
|---|---|---|---|
| 1 | 用語数 | 正本の TTL | 最初から |
| 2 | 一定期間（既定 90 日）一度も参照されていない用語の割合 | `term_access` | `P2B-05`（2026-09-10） |
| 3 | 責任者が未設定の用語 | `term_owners` | `P2B-04`（2026-09-10） |
| 4 | 一定期間再承認されていない用語 | `ontology_versions.approved_at` | 最初から |
| 5 | SHACL 違反の件数 | `ontology_core.shacl` | `P2A-05`（2026-09-09） |
| 6 | 未射影（`projected_at IS NULL`）の版 | `ontology_versions.projected_at` | 最初から |

**6 項目すべての原資料が揃った。** 残っているのは集計と提示である。

決めるべきことは 4 つある。

1. **用語の一覧をどこから取るか**（ストアか、正本か）
2. **「一定期間再承認されていない用語」をどう解釈するか**（承認は版単位で、用語単位ではない）
3. **測れなかった項目をどう返すか**
4. **誰が読めるか**

## 決定

### 1. 用語の一覧は**正本（Blob の TTL）から取る**。ストアから取らない

現在の承認済み版の TTL を Blob から読んで解析し、その名前空間が発行した IRI（`base_iri` を接頭辞に持つ主語）を用語とする。

**ストアから取ってはいけない。** トリプルストアは再構築可能な射影であって正本ではない（[ADR-0002](0002-triple-store-as-rebuildable-projection.md)、不変条件1）。ストアが空のときにストアを数えると、**「用語数 0、未参照 0 件、責任者未設定 0 件」= 完全に健全**という報告になる。

**これは健全性指標として最悪の壊れ方である。** 障害が起きているときに「健全」と報告する。`P2A-05` で「検証できなかった」を「違反ゼロ」と混同しないと決めたのと、[ADR-0016](0016-semantic-diff.md) 決定5 で「計算できなかった」を「差分が無い」と混同しないと決めたのと、同じ形の判断である。

**承認済み版が無ければ「用語 0」で正しい。** その名前空間はまだエージェントに何も渡していない。これは障害ではなく事実なので、そう報告する（`current_version` が `null` になるので区別できる）。

### 2. 「一定期間再承認されていない」は**版単位で測る**。用語単位に見せない

ADR-0009 の原文は「一定期間再承認されていない**用語**」だが、**このシステムの承認は版単位である**（[ADR-0010](0010-approval-and-projection.md) 決定2）。用語単位の承認は存在しないので、用語単位の「再承認の古さ」は計算できない。

**存在しない粒度をあるように見せない。** 現在の承認済み版が承認されてから何日経ったか（`approval_age_days`）を報告する。用語ごとの値を捏造して並べるより、**測れる粒度で正直に報告する**ほうがよい。

（用語単位で測りたいなら、その用語を最後に変更した版を差分から辿る必要がある。`P2B-09` の意味的差分を版の連鎖に適用すれば理論上は求まるが、**空白ノードの上限で計算できない版があり**（ADR-0016 決定5）、指標の一部が穴になる。未解決事項に置く。）

### 3. **測れなかった項目は `null` にし、理由を別に返す**

各項目は `int` か `null` で返す。`null` は「測れなかった」であり、**`0` とは違う**。加えて `unavailable` に「どの項目がなぜ測れなかったか」を並べる。

```json
{
  "namespace": "retail-core",
  "current_version": "2.0.0",
  "term_count": 42,
  "unreferenced_count": 7,
  "without_owner_count": 12,
  "approval_age_days": 5,
  "shacl_violation_count": 0,
  "unprojected_version_count": 1,
  "unavailable": []
}
```

Blob へ到達できなければ用語の一覧が作れないので、`term_count` / `unreferenced_count` / `without_owner_count` / `shacl_violation_count` が `null` になり、`unavailable` に理由が入る。**PostgreSQL だけで測れる項目（`approval_age_days`、`unprojected_version_count`）はそのまま返る。**

**部分的に測れたことを「全部測れなかった」にもしない。** 測れたものは返し、測れなかったものだけを `null` にする。「全部か無か」にすると、Blob の一時的な不調で未射影の版の数も見えなくなる。

### 4. `data-analyst` が読める

指標は**件数だけ**を返す（誰が責任者かは返さない）。個人を特定しないので、[ADR-0018](0018-context-access-log.md) 決定5 で `term_access` の集約を分析者に開いたのと同じ判断でよい。

**指標に強い権限を要求すると、指標が使われなくなる。** 「測っていないものは致命的になるまで見えない」という決定5 の趣旨は、見られることが前提である。

ただし**用語 IRI の一覧はオプトインにする**（`include_terms=true`）。件数だけなら軽いが、一覧は名前空間の規模に比例する。既定で返さないのは応答を小さく保つためで、権限の話ではない。

## 検討した代替案

### 用語の一覧をストア（SPARQL）から取る

TTL の解析が要らず速い。**却下**: 決定1 の理由。**ストアが空のときに「完全に健全」と報告する。** 健全性指標として最悪の壊れ方である。

### 指標を定期的に計算して保存する（スナップショット）

応答が速く、時系列で追える。**却下（将来の選択肢として残す）**: (1) 定期実行の仕組み（ACA Jobs）を持ち込む判断が別に必要で、この ADR の範囲を超える (2) **まず「今の値が見える」ことが要る**。時系列は次の段である (3) 保存すると「いつの値か」を常に気にしなければならず、**古い値を今の値と誤解する**危険が増える。オンデマンドなら常に今である。

### 測れなかった項目を `0` で返す

呼び出し側の型が単純になる。**却下**: このリポジトリが繰り返し避けている形そのものである。**「測れなかった」を「問題ゼロ」と報告するのは、健全性指標の目的に正面から反する。**

### 測れなかったら全体を 502 にする

「部分的に嘘」を作らない。**却下**: 決定3 の理由。Blob の一時的な不調で、PostgreSQL だけで測れる項目（未射影の版）まで見えなくなる。**測れたものは返す。**

### 「再承認されていない用語」を用語単位で計算する（差分の連鎖を辿る）

ADR-0009 の原文に忠実。**却下（未解決に送る）**: 意味的差分は空白ノードが多い版で計算できない（[ADR-0016](0016-semantic-diff.md) 決定5）。**指標の一部だけが穴になる状態**は、指標全体の信頼を落とす。版単位で正直に測るほうが先である。

### 健全性の総合スコアを出す

一目で分かる。**却下**: [ADR-0009](0009-ontology-operations.md) が既に却下している（「品質スコアでリリースをゲートする」）。**点数が下がった理由が行動に結びつかない。** 項目ごとの生の値を返す。

## 結果（トレードオフ・影響）

### 得られるもの

- **[ADR-0009](0009-ontology-operations.md) 決定5 の 6 項目が測れる。** Phase 2 柱 B の「健全性が測れる」完了条件を満たす
- **廃止（[ADR-0017](0017-deprecation-lifecycle.md)）の判断に根拠が付く。** 「使われていない用語」が分かって初めて、何を廃止すべきかを決められる
- **責任者（[ADR-0015](0015-term-owners.md)）の空白が見える。** 「責任者のいない用語は誰も保守しない」（ADR-0009）が可視化される
- **測れなかったことが見える。** 障害時に「健全」と報告しない

### 受け入れるコスト

- **TTL の解析コストが乗る。** 現在の承認済み版を Blob から読んで rdflib で解析する（実測 約 1.0 秒/MB）。オンデマンドの運用者向けの口なので許容する
- **「再承認されていない」は版単位でしか測れない。** ADR-0009 の原文（用語単位）には届かない
- **SHACL 違反は基本的に 0 になる。** `approve` が違反をブロックするので（`P2A-05`）、**構造上ほぼ常に 0** である。`P2A-05` より前に承認された版と、shape 自身の問題を拾うためだけに残す
- **一度も参照されていない用語と、90 日参照されていない用語を区別しない。** `term_access` に行が無い用語は「参照されたことがない」だが、指標としてはどちらも「未参照」である
- **時系列が無い。** 「悪化しているか」は分からない

### 影響を受ける他の決定

- **[ADR-0009](0009-ontology-operations.md) 決定5**: 実装される。「再承認されていない用語」は**版単位**と解釈した
- **[ADR-0018](0018-context-access-log.md)**: `term_access` が指標の原資料として使われる。**集約がイベントより長生きする**という決定がここで効く（保持期間を過ぎたイベントを消しても「90 日参照されていない」が計算できる）
- **[ADR-0002](0002-triple-store-as-rebuildable-projection.md)**: 「射影から測らない」を指標にも適用した

### 未解決のまま残す問い

- **用語単位の「再承認の古さ」**（差分の連鎖を辿る必要があり、空白ノードの上限で穴があく）
- **指標の時系列**（スナップショットの保存と、定期実行の仕組み）
- **しきい値と警告**（「未参照が 30% を超えたら警告」のような判断。何を異常とするかは利用者の運用による）
- **名前空間をまたぐ集計**（`platform-admin` 向けの全体像。権限判定が名前空間単位では収まらない）

## 補記: 廃止された先を指すマッピングの 2 項目を足した (2026-09-12、`P2B-21`)

[ADR-0037](0037-deprecated-target-metric.md) が `deprecated_target_mapping_count`
と `unknown_target_mapping_count` を足した。

**この 2 項目は `null` にならない。** 決定3 の規則の例外ではなく、
**同じ規則をより細かい粒度で適用した結果**である。決定3 は「項目が測れたか」で
分岐するが、マッピングの先の生死は**1 件ごとに**調べられたかどうかが決まる。
細かい粒度で分けられるなら、項目ごと落とす必要が無い。

決定3 の「**部分的に測れたことを『全部測れなかった』にもしない**」を、
項目の中でも守ったということである。

**指標が呼び出し元に依存するようになった。** マッピングの先の生死は相手の
名前空間への権限に依存する([ADR-0030](0030-mapping-target-lifecycle.md) 決定1)。
決定4(`data-analyst` が読める)は変えていない — **呼び出し元の権限で数える限り、
その呼び出し元が一覧で 1 件ずつ読める情報しか出ない。**
