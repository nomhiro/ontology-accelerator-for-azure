# ADR-0049: 依存関係のライセンスを CI で検査する — 判定できなかったものを通さない

- **状態**: 採択
- **日付**: 2026-09-13
- **関連タスク**: `P4-03`
- **関連 ADR**: [ADR-0005](0005-reasoner-boundary.md)(推論器の境界と LGPL)、
  [ADR-0008](0008-independent-implementation.md)(独立実装とライセンス)、
  [ADR-0021](0021-owl-reasoning-in-ci.md)(HermiT / JFact の不在を CI で検査)、
  [ADR-0046](0046-virtual-knowledge-graph.md)(JDBC ドライバの同梱)

## コンテキスト

この製品は Apache-2.0 で配布する。そのため**同梱できるライセンスに制約が
ある**。`docs/third-party-licenses.md` が主要コンポーネントを手で表にし、
`owlready2`(LGPL-3.0)や ROBOT(配布 jar に HermiT を同梱)を却下した記録を
残している。

**手で維持している表は古くなる。** そして同じ文書がこう書いていた。

> 今 CI が機械的に守っているのは「HermiT / JFact が入っていないこと」だけで、
> **新しいコピーレフト依存が別の名前で入ってきた場合は捕まえられません。**

実際、今日 1 日で 3 つの依存が増えた(cytoscape / `@azure/msal-browser` /
pgjdbc + mssql-jdbc)。**どれも手で確認した。** 手で確認できたのは、
増えたことを知っていたからである。

### 実測したライセンス表記の実態

設計の前に測った。

| 生態系 | 配布物の数 | ライセンスの綴りの種類 |
|---|---|---|
| Python(uv) | 83 | **19 通り** |
| Node(pnpm) | 205 | 8 通り |

**綴りは揺れる。** 同じ Apache-2.0 が `Apache-2.0` / `Apache 2.0` /
`Apache License 2.0` / `Apache Software License` の 4 通りで現れた。

**3 つの配布物は `License` 欄に全文を書いていた**(`html5rdf` 1,083 文字 /
`isodate` 1,608 文字 / **`pyshacl` 11,491 文字**)。

## 決定

### 決定1: 判定できなかったものを「問題なし」にしない

**これがこの検査の設計の中心である。**

綴りを寄せる表(`_ALIASES`)に無いものは `unknown` として**検査を落とす**。

「知らない綴りだから通す」を 1 度でも許すと、**この検査は「緑なのに何も
検証していない」状態になる** — しかも、そうなっていることが緑からは
分からない。このリポジトリが繰り返している判断
(ADR-0016 決定5 / ADR-0021 決定1 / ADR-0025 決定3 / ADR-0030 決定2 /
ADR-0041 決定2 / ADR-0047 決定2)と同じ形である。

**却下した代替案: 知らないライセンスを警告にとどめる。** 「落ちると
開発が止まる」という理由は分かるが、**警告は読まれない**。落とすほうが
正しく、対処も軽い(綴りを 1 行足すか、許諾リストを広げて理由を書く)。

### 決定2: 許諾リストを広げるのは人の判断である

`ALLOWED` を広げるときは `docs/third-party-licenses.md` に理由を書く。
**スクリプトが自動で学習してはいけない** — 「前に通ったから通す」は
判断の記録を消す。

`_ALIASES` に足すのも同じである。**実測した綴りだけを入れる** —
「たぶん Apache だろう」で足すと、この検査は意味を失う。

### 決定3: SPDX の複合式を意味どおりに評価する

| 式 | 判定 |
|---|---|
| `A OR B` | **どちらか一方が許諾済みなら許諾済み**(選べる) |
| `A AND B` | **両方が許諾済みでなければ通さない**(両方に従う必要がある) |
| `OR` と `AND` を混ぜた式 | **`unknown`**(人に回す) |

最後の行が重要である。優先順位の解釈が要るので**推測で通さない**。
実際には今の依存に混在式は無いが、**無いことを確かめてから通すのと、
推測で通すのは違う。**

### 決定4: `License` 欄の全文を読まない。分類子へ回す

優先順は **`License-Expression`(PEP 639 の SPDX 式)→ `License`(短いときだけ)
→ `Classifier: License ::`** である。

`License` が 60 文字を超える、または改行を含むときは**全文が書かれている**
と見なして読まない。**全文から識別子を当てるのは推測になる。**

実測で、全文を入れていた 3 つはすべて分類子を持っていたので、この順で
判定できた。

**`BSD License` の分類子は 2-clause と 3-clause を区別しない。** どちらも
Apache-2.0 と両立するので `BSD` として許諾するが、**この検査は両者を
区別しない**ことを記録しておく(区別が必要になったら `License-Expression` を
持つ版へ上げるか、個別に確認する)。

### 決定5: 検査を実行できなかったことと、検査の結果を分ける

終了コードを 3 つに分ける。

| コード | 意味 |
|---|---|
| 0 | 全部許諾済み |
| 1 | **拒否または判定できないものがある** |
| 2 | **検査自体を実行できなかった**(`pnpm` が無い等) |

`pnpm` が無いときに 0 を返すと、**「ライセンスは全部確認済み」として CI が
緑になる**。Node 側を飛ばすのは `--python-only` を明示したときだけである。

**`set -e` の下で `cmd; rc=$?` が書けない**(CLAUDE.md)ことと同じ理由で、
多値の終了コードは呼び出し側で `rc=0; cmd || rc=$?` として読む。

### 決定6: Java 側とコンテナの基盤イメージはこの検査の範囲外にする。範囲外を明記する

見ていないものを、スクリプトの冒頭とこの ADR に**列挙する**。

| 見ていないもの | 今どう扱っているか |
|---|---|
| `containers/reasoner` の shade jar(67 依存) | `reasoner-check.test.sh` が **HermiT / JFact の不在**を検査。**依存全体のライセンスは見ていない**(`license-maven-plugin` を回す手順は文書にある) |
| Ontop の基盤イメージ(27 の同梱ライセンス) | 2026-09-13 に目視で確認(GPL 単独は無い)。ADR-0046 に記録 |
| JDBC ドライバ | `containers/ontop/Dockerfile` が SHA-256 で固定し、全文を `containers/ontop/jdbc-licenses/` に置く |
| Fuseki / postgres の基盤イメージ | 未検査 |

**「CI が通ったからライセンスは全部確認済み」と読まれないことが、
この列挙の目的である。**

**却下した代替案: Java 側も CI で回す。** `license-maven-plugin` を
`reasoner` ジョブに足せば集計できるが、**あのジョブは既に約 2 分かかる**
うえ、出力の形が Python / Node とまったく違うので判定を 2 系統持つことに
なる。`P4-02`(可観測性)以降で扱う。

## 帰結

### 得られるもの

- **新しいコピーレフト依存が別の名前で入ってきたら CI が止まる。**
  `docs/third-party-licenses.md` が「捕まえられない」と書いていた穴が閉じた
- **288 件を毎回見る。** 手で維持している表(主要コンポーネントのみ)とは
  範囲が違い、こちらは推移的依存を含む
- **判定できないものが必ず人の目に触れる。** 実装の途中で
  `Mozilla Public License 2.0 (MPL 2.0)` が `unknown` になり、
  **それで自分のバグ**(`strip("()")` が末尾の `)` を落とす)**に気づいた**

### 受け入れるコスト

- **依存を足すと検査が落ちることがある。** 新しい綴りが出るたびに
  `_ALIASES` へ 1 行足す(または許諾リストを広げて理由を書く)必要がある。
  **それは意図した摩擦である** — ライセンスを見ないまま依存が増えるより
  よい
- **`BSD` の 2-clause / 3-clause を区別しない**(決定4)
- **Java 側とコンテナの基盤イメージを見ていない**(決定6)
- **CI の `python` ジョブに pnpm のセットアップが増えた。** Node 側を
  同じジョブで検査するため(別ジョブにすると uv と pnpm の両方を 2 回
  用意することになる)

### 確かめていないこと

- **`pnpm licenses list` がワークスペース全体を見るか。** 実測では
  `apps/web` で実行して 205 件が返った(リポジトリのルートには
  `package.json` が無く `ERR_PNPM_NO_IMPORTER_MANIFEST_FOUND` になる)。
  **ワークスペースに 2 つ目の Node パッケージを足したときに拾えるかは
  確かめていない** — 足すときはここを見直すこと

## 実測に基づく検査をどこに置いたか

| 何を確かめるか | どこ |
|---|---|
| 綴りの寄せ / 複合式の意味論 / 全文を読まないこと | `packages/core/tests/test_license_check.py` |
| **判定できないものが終了コード 1 になること** | 同上 |
| **`pnpm` が無いときに 0 を返さないこと**(決定5) | 同上 |
| **実物の依存が全部許諾済みであること** | 同上(`test_実物の依存が全部許諾済みである`) |
| 許諾リストと拒否リストが重ならないこと | 同上 |
| **実データでガードが発火すること** | 手で確認(`MIT` を許諾リストから外すと 42 件・終了コード 1) |

**変異テストで 12 件の変異を当て、最初は 2 件が生き残った。**

- **混在式の検査を外しても落ちなかった。** テストが
  `MIT AND (GPL-3.0 OR Apache-2.0)` を使っており、検査を外しても
  **偶然 `unknown` になっていた**(`OR` で分割した断片がどちらも綴りとして
  読めないため)。**偶然通るテストは何も固定していない。**
  `MIT OR GPL-3.0 AND AGPL-3.0` を足した(この式は検査が無いと `allowed` になる)
- **「ライセンス情報が無い配布物」を `MIT` とみなしても落ちなかった。**
  実測では 83 件すべてに情報があったので、**その分岐は実物では通らない**。
  `distributions` を差し替えるテストを足した

どちらもテストを足して殺した(12/12)。
