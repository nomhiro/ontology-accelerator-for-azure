# ADR-0048: 仮想グラフへの照会をアクセスログに残す — 列を足して、既存の行の意味を変えない

- **状態**: 採択
- **日付**: 2026-09-13
- **関連タスク**: `P3-08`
- **関連 ADR**: [ADR-0018](0018-context-access-log.md)(アクセスログ)、
  [ADR-0046](0046-virtual-knowledge-graph.md)(仮想グラフ。決定13 をここで解く)、
  [ADR-0006](0006-ontology-versioning-and-audit.md)(監査)、
  [ADR-0025](0025-result-limit-enforcement.md)(切り詰めの記録)

## コンテキスト

`P3-01`(ADR-0046)で仮想グラフへの照会ができるようになった。**その経路が
返すのは顧客の実データである。** この製品でいちばん機密性の高い経路である。

**それが監査証跡に残っていなかった。** ADR-0046 決定13 はこう書いて
見送っていた。

> `access_events` の行は「どの**版**の何を返したか」を持つ形で、仮想グラフには
> 版が無い。`default_graph_version` を `NULL` で埋めると「承認済み版が
> なかった」と混ざる。

見送りは正しかった(混ぜるほうが悪い)が、**「説明可能・監査可能」を掲げる
製品で、いちばん機密性の高い経路だけ記録が無いのは筋が通らない**。
ADR-0006 決定4 は「エージェントへ提供したコンテキストのアクセスログ」を
監査の最後のピースと呼んでいる。

## 決定

### 決定1: `access_events` に `vkg_source` を足す。既存の行の意味は変えない

| `vkg_source` | 何の照会か |
|---|---|
| `NULL` | **オントロジーへの照会**(Fuseki)。**これは既存の全行と同じ意味である** |
| 非 `NULL` | そのソースの仮想グラフへの照会(Ontop) |

**列を足すときに既存の行の読み方が変わってはいけない。** 変わると
**過去の記録が信用できなくなる** — 「この行は新しい意味なのか古い意味なのか」
を後から判定できない。`NULL` を「オントロジーへの照会」にすることで、
マイグレーション前の全行がそのまま正しい。

**却下した代替案: 別の表(`vkg_access_events`)を作る。** 既存の行にまったく
触らない点は良いが、**「エージェントに何を渡したか」を 2 か所で引くことに
なる**。監査の問いは「この主体がこの期間に何を受け取ったか」であって、
「オントロジーから何を受け取ったか」ではない。1 つの時系列で読めるほうが
正しい。

**却下した代替案: 記録しない(現状維持)。** ADR-0046 決定13 の続きだが、
**列の形が合わないことは記録しない理由にならない** — 形を直せばよい。

### 決定2: `vkg_mapping_revision` を足す。これが版の代わりである

監査の問いは「**どの定義の入口を通して実データを返したか**」である。
仮想グラフでは R2RML マッピングの改訂がそれに当たる(マッピングは
ソースごとの不変改訂。ADR-0046 決定2)。

**この 2 列があるから `default_graph_version` の `NULL` が曖昧でなくなる。**

| `vkg_source` | `default_graph_version` が `NULL` の意味 |
|---|---|
| `NULL` | 承認済み版が無かった |
| 非 `NULL` | **版の概念が無い**(仮想グラフ) |

**`used_graph_clause` は常に偽である。** 仮想グラフには既定グラフしか無い
(ADR-0046 決定8 が `rr:graph` を禁じている)。

### 決定3: `term_access` は更新しない。構造で固定する

`term_access` は「**自分のオントロジーのどの用語が使われていないか**」に
答えるための表で、**行数がその名前空間の用語数で上限される**ことが設計の
一部である(ADR-0018 決定6、`TermAccessRow` の docstring)。

仮想グラフが返すのは**インスタンスの IRI** なので、入れると
**エージェントの稼働に比例して行が増える**。上限が消える。

しかも `returned_terms` は `base_iri` で前方一致するだけなので、
**`base_iri` がスラッシュ区切りの名前空間ではデータ IRI が用語として
数えられてしまう**。

| `base_iri` | データ IRI | 前方一致するか |
|---|---|---|
| `https://e.example/vkg#` | `https://e.example/vkg/data/customer/1` | しない |
| `https://e.example/vkg/` | `https://e.example/vkg/data/customer/1` | **する** |

**`build_vkg_access_record` は `terms` 引数を持たない。** コメントで
「渡さないこと」と書くのではなく、**渡せないようにする**。テストが
引数の不在を検査する。

### 決定4: 絞り込みは 2 つの別の引数にする

- `vkg_source=<名前>`: そのソースの仮想グラフへの照会だけ
- `ontology_only=true`: オントロジーへの照会だけ(`vkg_source IS NULL`)

**`vkg_source=None` を「オントロジーへの照会だけ」と解釈してはいけない。**
それは**絞り込まない既定と区別できない**。この製品が繰り返し避けている
「1 つの値に 2 つの意味を持たせる」形である。

索引は `(namespace, vkg_source, id)` を足した。「この顧客 DB に誰が何を
聞いたか」が監査の主用途になるためで、`id` を含めるのは並び順と
ページングの鍵が `id` であるため(ADR-0018 と同じ)。

### 決定5: 切り詰める前の行数を記録する

ADR-0025 決定6 と同じ判断である。「エージェントに何行渡したか」ではなく
「**何行返ろうとしたか**」でなければ、上限に張り付いているクエリを
見つけられない。

`CONSTRUCT` / `DESCRIBE` では**トリプル数を記録する**(行数は `NULL`)。
ADR-0046 決定14 は**上限を当てない**と決めたが、**記録しないとは決めて
いない** — 上限を当てないことと数えないことは別の判断である。

### 決定6: 記録に失敗しても照会は失敗させない

ADR-0018 決定3 と同じである。アクセスログは読み取りの副産物であって、
読み取りの前提条件ではない。**ただし「記録できなかった」を黙って
無かったことにはしない** — 警告としてログに残す。

### 決定7: 仮想グラフのクライアントを依存として注入する

ハンドラの中で `VirtualGraphClient()` を作っていたのを、
`VkgClientDep`(FastAPI の依存)に変えた。

**理由はテスト可能性である。** ハンドラの中で作ると、**アクセスログを
記録する経路を差し替えられない**。`P3-01` の時点では「照会が返るか」だけを
見ていたので問題にならなかったが、**そこが監査証跡になった以上、
経路を試験できなければならない**。

`blob_store` / `sparql_store` と同じ形にしてある。

## 帰結

### 得られるもの

- **いちばん機密性の高い経路が監査証跡に残る。** いつ・誰が・どのソースに・
  どのマッピングの改訂を通して・何行(何トリプル)受け取ったか
- **1 つの時系列で読める。** オントロジーへの照会と仮想グラフへの照会が
  同じ表に並ぶ
- **`default_graph_version` の `NULL` が曖昧でなくなった**(決定2)
- **ソースで絞れる。** 「この顧客 DB に誰が何を聞いたか」

### 受け入れるコスト

- **`access_events` が 2 列増えた。** 仮想グラフを使わない利用者には
  常に `NULL` の列が 2 つ増える
- **クエリ本文が残る。** 既存の行と同じ扱い(2,000 文字で切り詰め + 全文の
  ハッシュ)だが、**仮想グラフのクエリには顧客データの値が入りうる**
  (`FILTER(?name = "田中 太郎")` のような形)。これは既存の
  `access_events` と同じ性質の問題で、**保持ポリシー**(ADR-0019、`P2B-02`)と
  **`owner` だけが読める**(ADR-0018 決定5)ことで扱う。**新しい問題では
  ないが、仮想グラフでは値が実データになるので影響は大きい** — この点を
  README に書いた
- **`term_access` に何も残らない。** 「どの用語が実データに使われたか」は
  この経路からは分からない(決定3)。知りたいなら乖離の測定(`P3-05`)を使う

### 確かめていないこと

- **記録の量。** エージェントが仮想グラフを高頻度に叩くとイベントが増える。
  保持ポリシー(`P2B-02`)の既定値がその量に見合うかは測っていない

| **既存の行の意味が変わっていない**(決定1) | 同上 |
| **`term_access` を更新しない**(決定3)。引数が無いことも | 同上 |
| 切り詰める前の行数 / トリプル数(決定5) | 同上 |
