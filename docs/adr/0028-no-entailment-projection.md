# ADR-0028: 導出された含意を射影しない — 「少しだけ推論する」は「推論しない」より危険

- ステータス: 承認済み
- 日付: 2026-09-12

## コンテキスト

[ADR-0021](0021-owl-reasoning-in-ci.md)(`P2B-01`)で OWL 推論器(ELK)が CI に
入った。矛盾と充足不能クラスを検出する。**導出された含意をトリプルストアへ
射影するかは別の決定**として `P2B-15` に分離してあった。

射影したくなる理由は具体的である。**エージェントの SPARQL は推論しない。**

```turtle
ex:Premium  rdfs:subClassOf ex:Customer .
ex:Customer rdfs:subClassOf ex:Party .
```

このとき `SELECT ?s WHERE { ?s rdfs:subClassOf ex:Party }` は
**`ex:Customer` しか返さない**。`ex:Premium` は OWL の意味論では
`ex:Party` の部分クラスだが、**そのトリプルは書かれていない**。
エージェントは「Party の部分クラスは Customer だけ」と答える。

これは「AI エージェントに正しいコンテキストを渡す」という製品の目的に
直接かかわる。

## 決定

### 1. 導出された含意をストアに射影しない

理由が 4 つあり、**どれか 1 つでも致命的である**。

#### (a) ELK の結論は実用的なオントロジーではほぼ常に不完全である

ADR-0021 が実測した。ELK 0.6.0 はデータプロパティを扱えず、
**`Ontology satisfiability cannot be checked!` と警告して判定を諦める**。
業務用のオントロジーで属性を 1 つも持たないことは無いので、
**不完全は例外ではなく通常の状態**である。

射影すると、ストアに載るのは**主張された公理でも完全な演繹閉包でもない、
中途半端な部分閉包**になる。そしてエージェントには
**「導出されなかった」と「計算されなかった」を区別する手段が無い。**
ADR-0021 決定1 が JSON のフィールド名で守っている区別が、ここで消える。

#### (b) 射影は再構築可能でなければならない。推論の結果は再構築されない

不変条件1 は「トリプルストアは再構築可能な射影であり正本ではない」と言う。
**ローダ(`containers/fuseki/load-snapshot.sh`)は Blob の `.ttl` だけを読み、
推論器を走らせない。** したがって導出トリプルは**レプリカの再作成で静かに
消える**。

しかも `reconcile`([ADR-0013](0013-reconcile-repairs-observed-divergence.md))は
`ontology_versions` とストアの観測状態を突き合わせるだけで、
**含意の有無は見ていない**。つまり消えたことに誰も気づけない。
**「あるときは推論結果が返り、レプリカが再起動すると返らない」**は、
このリポジトリで最も避けたい形(強制していないものを強制していると
誤認させる)の変種である。

#### (c) 主張と導出が区別できなくなる

名前付きグラフに混ぜた時点で、`ex:Premium rdfs:subClassOf ex:Party` が
**人が承認した定義なのか推論器が出したのか**分からなくなる。

[ADR-0006](0006-ontology-versioning-and-audit.md) の中核価値は
「**誰が承認した定義に基づく答えかを説明できること**」である。混ぜることは
その価値を直接壊す。

#### (d) 不変リビジョンの中身が推論器の版で変わる

不変条件7 は「公開済みの版を書き換えない」と言う。導出トリプルを版のグラフに
入れると、**ELK 0.6.0 → 0.7.0 で同じ版の内容が変わる**。
「不変リビジョン」が推論器の実装に依存して意味を変えるのは、
バージョン固定参照(ADR-0006 決定2)の前提を崩す。

### 2. クエリ時推論(Jena の `ja:InfModel`)も有効にしない

Fuseki の assembler は `ja:InfModel` + `ja:reasoner` で RDFS / OWL-lite の
ルール推論を組み込める。**採らない。**

- (c) と同じ問題が残る(主張と導出が区別できない)
- Jena の `RDFSRuleReasoner` / `OWLMicroReasoner` は**また別の不完全な断片**
  である。「推論しない」を「文書化されていない部分的な推論をする」に
  取り替えるだけになる
- ルール推論のコストはクエリごとにかかり、`arq:queryTimeout`
  (10 秒 / 30 秒)の予測可能性を壊す

**そして最大の理由: 「少しだけ推論する」は「推論しない」より危険である。**
一部の含意が返ると、エージェントは**このエンドポイントは推論する**と
結論する。そのうえで返らなかった含意を「成り立たない」と読む。
**何もしなければ、少なくとも一貫して何もしない。**

### 3. 「推論しない」ことをエージェントに明示し、プロパティパスを案内する

決定1・2 で失われたものを、**標準の SPARQL で埋められる範囲は埋める。**

| 知りたいこと | 書き方 |
|---|---|
| ある用語の下位クラス全部 | `?s rdfs:subClassOf+ ex:Party` |
| ある個体が属するクラス全部 | `ex:alice rdf:type/rdfs:subClassOf* ?c` |
| 上位の概念全部(SKOS) | `ex:x skos:broader+ ?c` |

SPARQL 1.1 のプロパティパスは**推論ではなくグラフの到達可能性**なので、
ストアの設定に依存せず、主張されたトリプルだけを辿る。
**つまり (c) の問題が無い** — 返ってきた経路はすべて誰かが承認した公理である。

これを MCP の `sparql_query` のツール説明と Core API の `/sparql` に書く。
**エージェントはヘッダも ADR も読まないので、ツール説明に書かなければ
届かない**([ADR-0017](0017-deprecation-lifecycle.md) 決定3 と同じ判断)。

**プロパティパスで届かないものは届かない。** `owl:someValuesFrom` を通じた
含意や `owl:equivalentClass` の対称性、互いに素なクラスからの帰結は
パスでは辿れない。そのことも書く — **書かないと「パスを使えば推論と同じ」
と読まれる。**

### 4. 矛盾の検出は CI が担う。射影しないことで失われる価値はそこではない

決定1 で射影しないと決めても、**「このオントロジーは論理的に壊れている」を
見つける機能は失われていない**。それは ADR-0021 の CI が担っている。

失われるのは「エージェントが推論結果を引ける」ことだけで、それは決定3 で
部分的に埋める。**区別して書いておく** — 「推論を射影しない」を
「矛盾を検査しない」と読まれないため。

### 5. 再検討の条件を 3 つとも満たしたときに限る

`P2B-15` を閉じるが、**開け直す条件を明記する。3 つすべてが必要**である。

1. **完全な OWL 2 DL 推論器が配布物に入る。** いまは ADR-0005 決定4 で
   HermiT(LGPL-3.0)を同梱していない。不完全な推論器では (a) が残る
2. **ローダが起動時に含意を再計算できる。** 起動時間の予算に収まること
   (ADR-0002 の再構築時間は既に追跡中のリスクである)。これが無いと (b) が残る
3. **導出トリプルが別の名前付きグラフに載り、不完全性の印が付く。**
   `urn:ontology:entailment/<ns>/<version>` のような別グラフにして、
   エージェントが `GRAPH` 句で明示的に取りに行く形。これが無いと (c) が残る

**どれか 1 つだけでは足りない。** 3 つのうち 1 つを満たしただけで進めると、
残り 2 つの問題がそのまま本番に出る。

## 検討した代替案

### 導出トリプルを別の名前付きグラフに射影する(決定5 の 3 番だけを実施する)

**却下(今は)。** (c) の「主張と導出の区別」は解ける。エージェントは
`GRAPH` 句で明示的に取りに行くので、混ざらない。

却下理由: **(a) と (b) が残る。** 部分閉包であることは変わらず、レプリカの
再作成で静かに消えることも変わらない。**「取りに行ったら空だった」が
「含意が無い」と読める**状態を作るだけである。

### `approve` のときに含意を計算して TTL に焼き込む

**却下。** 正本に入るので (b) が解け、不変リビジョンとしても一貫する。

却下理由: 3 つある。
1. **不変条件15 に反する** — 承認時の検査は正本の TTL に対して行うと決めて
   いるが、これは検査ではなく**正本の書き換え**である
2. **ADR-0005 決定3 が `approve` の同期パスに推論を入れないと決めている**
   (実行時間が予測しづらい)
3. **(a) と (c) が残る。** 焼き込んだ部分閉包は、後から主張と区別できない

### エージェント向けの推論用エンドポイントを別に立てる

**却下(今は)。** ADR-0005 の代替案「OWL 推論を同期 API として提供する」が
既に検討して却下している(推論サービスコンテナの常時稼働コストと
実行時間の予測不能性)。ここで蒸し返す新しい事実は無い。

### プロパティパスを案内せず、「推論しない」とだけ書く

**却下。** 正確ではある。

却下理由: **正確だが役に立たない。** エージェントは階層を辿る手段が要る。
「できません」だけを返すと、エージェントは直接の
`rdfs:subClassOf` で満足して**不完全な答えを自信を持って返す**。
届く範囲を示すほうが安全である。

## 結果(トレードオフ・影響)

### 受け入れるコスト

- **OWL の含意はエージェントから引けない。** プロパティパスで辿れるのは
  推移的な骨格だけで、`owl:someValuesFrom` や `owl:equivalentClass` を
  通じた含意、互いに素なクラスからの帰結は届かない
- **プロパティパスを書けるかはエージェント任せである。** ツール説明に
  書くことしかできない
- **`P2B-15` は「やらない」で閉じる。** 開け直す条件は決定5 に書いた

### 得られるもの

- **一貫して推論しない。** 「あるときは返り、あるときは返らない」を作らない
- **主張と導出が混ざらない。** 返ってきたトリプルはすべて誰かが承認した公理
  であり続ける(ADR-0006 の中核価値)
- **射影が再構築可能なままである**(不変条件1)
- **届く範囲がエージェントに伝わる**(決定3)

### 影響を受ける他の決定

- [ADR-0002](0002-triple-store-as-rebuildable-projection.md) — 「再構築可能」が
  含意の射影を実質的に禁じていることが、ここで明確になった
- [ADR-0021](0021-owl-reasoning-in-ci.md) — 却下リストの「導出された含意を
  射影する(`P2B-15` として分離)」に決着を付けた
- [ADR-0005](0005-reasoner-boundary.md) 決定3 — `approve` に推論を入れない
  判断を、焼き込み案の却下理由として再利用した
